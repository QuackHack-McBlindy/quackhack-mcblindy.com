Why this might be a first

Every home automation system I know of picks between two formats: structured data (YAML, JSON) or visual flows (Node-RED's drag-and-drop). Both work. Both are how almost everyone does it. Neither is what a house actually speaks.

This file is neither. It's plaintext Nix — typed, version-controlled, and readable end-to-end — with the automation actions written as sentences in Swedish. Not as comments above the code. As the actual code.

Home Assistant

YAML 
- alias: Kitchen fan on motion
  trigger:
    - platform: state
      entity_id: sensor.kitchen_motion
      to: 'on'
  action:
    - service: switch.turn_on
      target:
        entity_id: switch.kitchen_fan

This house

Swedish sentence 
"om fläkten drar mer än tjugo watt
så stäng fläkten om etthundraåttio
sekunder sedan släck köket långsamt"

The first two are configuration. The third is a wish. The system reads it, resolves every parameter, and does exactly what you asked. If the fan draws more than 20 W, turn it off in 180 s and fade the kitchen down. Not because the YAML said so — because you said so.

What's actually in one file

Six automation categories, each with its own trigger shape. Every action under every category is a plain Swedish sentence. Here's the map, with a real quote from the file under each.

1

MQTT-triggered

Fires when a device publishes to a Zigbee topic. The alarm, the timer, the leak detector, the crypto ticker — all live here.

"skicka en notis om ⏰ ALARM: Wake up! samt flasha ljuset"
2

Room actions

Fires on door open/close or motion detected/not detected. Per-room.

"om fläkten drar mer än tjugo watt så stäng fläkten om etthundraåttio sekunder sedan släck köket långsamt"
3

Global actions

Fires on any device that demands attention — water leak, smoke detector. Runs across every room at once.

"säg ELD ELD ELD ELD samt vänta femton sekunder sedan säg ELD ELD ELD ELD!"
4

Dimmer actions

Fires on button press, button hold, and release from the zigbee dimmers in each room.

"släck alla lampor sedan stäng av fläkten"
5

Time-based

Fires on a cron-style schedule. Wake-up alarm, weekend cancellation, TV guide scrape, battery check.

"väck mig klockan elva och trettio"
6

Presence-based

Fires on home/away transitions detected by phone probes. Arrival and departure routines.

"skicka en notis om 🏠 ❌ LEFT HOME! samt släck alla lampor"

Björklöven is a specific hockey team in a specific Swedish city. The config isn't a framework for anyone — it's a framework for one household, built by one person, and it happens to have a laugh at itself. That's why the phrase "config in plaintext" matters: when the config is plain enough to read, the personality shows through. YAML flattens it. Swedish keeps it.

The honest caveat

I don't know this is a first. I looked. I searched for other Nix-based home automation modules, other natural-language configs, other single-file complete-house automations. I found plenty of Nix packaging of Home Assistant and Node-RED — but those are YAML-based systems wrapped in Nix, not Nix-native configurations. I found OpenHAB's DSL and Home Assistant's templating engine — both closer, neither natural language. I couldn't find anyone doing the specific combination that this file does.

"Couldn't find" isn't "doesn't exist." If you know of prior art, please tell me. I'll be happy to be second. But until then, I'll keep the "possibly" in the claim, and let the file speak for itself.

One honest asterisk. "One file" is the behaviour — rooms, automations, scenes, TV, dashboard. The device list lives in devices.nix and the dashboard pages in dashboard.nix, both imported at the top of myHouse.nix. Every large Nix module imports small modules. What's unusual is that the entire logic of the house fits in one file you can actually read front to back.

Not a first by right. A first by
best guess and an honest search.
